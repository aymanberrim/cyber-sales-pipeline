# 7 · Learn

**Input:** outcomes from every stage — sends, replies, calls, red-teams, pilots, and the vulnerabilities found.
**Output:** a tightened ICP rule, sharper message angles, and a one-page weekly read for the founder.
**Exit criterion:** each week, the channel's own medians replace the default thresholds, and win/loss is fed back into stage 1.
**Metric:** twelve channel metrics tracked; the north-star = red-teams booked per week.

## The cadence

- **Daily (15 min):** empty the reply and safety-net queues; every lead has one dated next action.
- **Weekly (60 min):** review the funnel — sends → replies → calls → red-teams → pilots; re-cut any segment under 3% reply after 60 sends; one-page summary to the founder.
- **Monthly:** refresh triggers and the ICP rule; re-check which vulnerability angle is converting.

## What the red-team findings teach the top of the funnel

The vendor's own output is a feedback signal most GTM motions do not have: the vulnerability classes that land most often, on which stacks, become the **lead angle** for the next batch. If indirect prompt injection on RAG setups converts best, the RAG segment gets priority and the message leads with it. The product's findings re-aim the targeting.

## Pause triggers

Open rate < 35% or reply rate < 3% over a batch pauses sending for that group and sends it back to **3 · Segment** to be re-cut. Every number in this repo is a default until the channel has eight weeks of its own data; then the medians rule.
